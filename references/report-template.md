## 第一章 执行摘要

> **LLM 务必用自然语言写**，综合数据、问题、健康度评分，不要照抄占位。  
> 长度 4-8 段；适合"客户领导 30 秒看完了解整体"的级别。

应当包含：

1. **整体评价句**：「本次巡检覆盖 X 节点（主 X 从 X），运行整体 [稳定 / 良好 / 存在关键风险]，识别问题共 N 项」
2. **核心风险点**：列 3-5 个最值得 customer 关注的（按 P0 → P1 优先）
3. **健康度评分**：6 维度 + 总分（百分制，最低 50）
4. **本次报告范围**：采集时间 / 数据完整度 / 哪些章节因采集不全降级
5. **行动建议总览**：「立即处理 X 项 / 近期 X 项 / 中长期 X 项」
6. **报告导航**：「详细分析见第 X 章；行动计划见第 16 章」

## 模板使用注意

1. **不要省略章节** — 数据为空时填"未发现"或"采集脚本未覆盖此项"
2. **不要保留占位符** — `{{xxx}}` 必须替换或删除
3. **第一章和第十七章用自然语言写**，其它章节以表格 + 列表为主
4. **行动计划（16.x）必须列规则的 action / SQL 字段**，不要自己编造
5. **不要把规则的触发表达式（如 `node.memUsagePct > 90`）写进报告** — 这是给 LLM 看的，不是给客户看的
6. **采集数据脱敏识别** — 看到 `masked-hostname` 等占位字符串时，按 `Master_Server_Id` / IP 兜底识别拓扑，不要在报告里抱怨"数据脱敏"
7. **客户访谈信息缺失** — 业务背景章节（容灾 / 业务时段 / 项目正式名）如有 `references/interview-guide.md` 填充的信息则用；否则标注"访谈信息待补充"
